# System Specification

## 1. Project

**Name:** WhatsApp File Echo Bot

**Purpose:** Build a lightweight personal WhatsApp bot that returns
received media/files to the original sender.

## 2. Functional Requirements

### FR-001 Authentication

The bot must:

-   Use Baileys authentication.
-   Support the authentication flow appropriate for the installed
    Baileys version.
-   Persist authentication credentials.
-   Reuse valid credentials after restart.
-   Keep authentication data outside source code.
-   Never commit authentication data to Git.

### FR-002 Message Handling

For every incoming message:

1.  Validate the message.
2.  Ignore messages generated by the bot itself.
3.  Identify the sender.
4.  Determine whether media is present.
5.  Ignore text-only messages.
6.  Process media messages.

### FR-003 Sender Identification

The destination must be derived from the incoming message.

Do not hardcode a destination number.

Conceptually:

``` text
incoming message
      ↓
sender JID
      ↓
send response to sender
```

The implementation must use the correct sender metadata for the
installed Baileys version.

### FR-004 Media Support

The initial implementation should support common:

-   Documents
-   Images
-   Videos
-   Audio

At minimum, test:

-   PDF
-   DOCX
-   JPG/PNG
-   MP4
-   MP3

### FR-005 Media Processing

For a media message:

1.  Determine media type.
2.  Download media using the recommended Baileys API.
3.  Store it temporarily when necessary.
4.  Preserve filename and MIME type where supported.
5.  Send it back to the original sender.

### FR-006 Cleanup

Temporary files must be removed after successful processing and after
failures where possible.

Use reliable cleanup logic such as `try/finally`.

The bot must not accumulate temporary files indefinitely.

### FR-007 Self-Message Protection

The bot must never process its own outgoing media as a new incoming
request.

This must prevent an infinite loop:

``` text
User → file → Bot
             ↓
          file back
             ↓
        Bot receives it
             ↓
          file back
             ↓
             ...
```

### FR-008 Error Handling

Handle at minimum:

-   Authentication errors
-   Connection loss
-   Reconnection
-   Invalid messages
-   Unsupported media
-   Download failures
-   Send failures
-   Filesystem failures
-   Cleanup failures

A single failed message must not terminate the application.

### FR-009 Logging

Use readable logs such as:

``` text
[INFO] Starting WhatsApp bot
[INFO] Connecting
[INFO] Authentication successful
[INFO] Bot ready
[INFO] Media received
[INFO] Sender: <redacted-or-safe-id>
[INFO] Filename: tugas.pdf
[INFO] Downloading media
[INFO] Sending media
[INFO] Media sent successfully
[INFO] Temporary file deleted
```

Do not log credentials, authentication state, file contents, or
unnecessary sensitive data.

## 3. Security Requirements

The following must not be committed:

``` text
.env
auth/
temp/
node_modules/
dist/
*.log
```

No credentials may be hardcoded.

Files should not be stored permanently unless explicitly required later.

## 4. Non-Functional Requirements

### Lightweight

Keep dependencies and architecture minimal.

### Maintainable

Use clear TypeScript modules with focused responsibilities.

### Reliable

One failed message must not crash the entire process.

### Portable

The application should work on:

-   Windows
-   WSL
-   Linux

without major code changes.

### Privacy

Received files should only exist temporarily during processing.

## 5. Suggested Architecture

``` text
WhatsApp
   ↓
Baileys Client
   ↓
Message Handler
   ↓
Media Detection
   ↓
Sender Identification
   ↓
Media Handler
   ↓
Temporary Storage
   ↓
Send Media to Sender
   ↓
Cleanup
```

Suggested project structure:

``` text
whatsapp-file-bot/
├── src/
│   ├── index.ts
│   ├── whatsapp.ts
│   ├── messageHandler.ts
│   ├── mediaHandler.ts
│   └── fileManager.ts
├── auth/
├── temp/
├── .env
├── .env.example
├── .gitignore
├── package.json
├── tsconfig.json
├── README.md
├── SPEC.md
├── TASKS.md
└── AGENTS.md
```

The structure may be simplified when appropriate. Avoid unnecessary
abstractions.

## 6. Scope

### In Scope

-   WhatsApp authentication
-   Session persistence
-   Message receiving
-   Media detection
-   Sender identification
-   Temporary media handling
-   Media echo
-   Cleanup
-   Logging
-   Error handling
-   Reconnection
-   Local development

### Out of Scope

Do not implement:

-   Database
-   Redis
-   Web dashboard
-   Frontend
-   REST API
-   Cloud storage
-   AI
-   User management
-   Payment system
-   Docker
-   VPS deployment
-   Cloud deployment
-   Scheduled jobs
-   Analytics
-   Admin panel
-   Complex command system

## 7. Definition of Done

The initial version is complete when:

-   [x] WhatsApp authentication works.
-   [x] Authentication persists across restart.
-   [x] Bot receives messages.
-   [x] Bot identifies sender.
-   [x] Bot detects media.
-   [x] Bot downloads media.
-   [x] Bot sends media back to sender.
-   [x] Returned file is valid.
-   [x] Temporary file is deleted.
-   [x] Self-message loops are prevented.
-   [x] Connection failures are handled.
-   [x] Processing errors do not crash the application.
-   [x] Logs are readable.
-   [x] Authentication data is excluded from Git.
-   [x] Local setup is documented.
